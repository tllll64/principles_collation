## 0｜需求背景与理解

### 0.1 需求背景

当前页面为国际汇款产品「After Sending」选择汇款到微信之后的状态页，用于展示汇款后交易状态并引导用户完成后续收款。现由交易时间线（Timeline）、交易状态（Transfer Status）、子状态（Sub-status）、收款通知（ShareLink / Recipient Notification）组成，整体偏「状态展示」。

诉求：将页面从**「状态展示页」升级为「交易推进页」**，在展示状态的同时更主动地引导用户完成收款、推动交易尽快完成。重点覆盖两类场景：

- **自汇自收（Self → Self）**：用户希望尽快前往微信完成收款。
- **自汇他收（Self → Others）**：用户希望尽快通知收款人并推动其完成收款。

约束：不新增后台能力；通过信息架构、CTA、文案、交互等综合手段提升 CTA 点击率、收款完成率，同时减少困惑、行为中止与客服咨询。原型探索阶段，不受现有结构与视觉布局限制。

### 0.2 需求理解（经 4 项澄清后锁定）

| 澄清项 | 结论 |
|---|---|
| **场景区分方式** | 一套页面、内部按场景条件渲染。"当前完全不区分自收/他收"本身就是核心缺陷之一——现页面用"他收"措辞硬套所有人，自收用户看到"通知自己"逻辑不成立 |
| **能否感知对方是否完成 setup** | 感知不到，**Timeline 节点逻辑与文案不动**。推进不能靠探测对方进度做闭环，只能把用户自己该做的动作讲清、催到位 |
| **是否有时效抓手** | 有。**超过 24 小时未收款，款项原路退回汇款人**。这是真实时效，可正当用作推进抓手 |
| **北极星** | **更少困惑 + 明确下一步**。点击率、完成率是它的结果，不靠强推或制造焦虑换取 |

**一句话问题定义**：页面把"已发生的四步"摆在视觉主位、把"当前唯一该做的事"压成时间线末端一句灰字加一个按钮，且不分自收/他收地对所有人说同一套"通知对方"的话——导致自收用户困惑、他收用户没被有效推动，且没人告诉他们"24 小时不动钱会退回"。

- **L1-12（同类交互一致）**：本次是单页原型探索，不涉及跨页一致性；自收/他收差异属"按任务必要区分"，在 L1-12 边界内。
- **L1-14 / L1-15（归属 / 扫读）**：与本次相关但偏执行细节，会在具体排版阶段自然承接，不作为驱动性原则单列以免召回被稀释。

## 2｜设计目标

**核心问题**：页面「告知发生了什么」有余、「帮用户完成下一步」不足；不分场景；未告知 24h 退回时效。

- **用户目标（北极星）**：用户看完这一屏，1 眼知道 **现在卡在谁那 / 我该做什么 / 不做会怎样**，并能立刻做（L1-05 / L1-08）。
- **业务目标（结果，非手段）**：CTA 点击率、收款完成率上升，困惑 / 中止 / 客服咨询下降——它们是「清晰」的自然结果，不靠强推或制造焦虑换取（L1-02）。

## 3｜设计说明

### 3.1 信息架构：从"按后台模块"翻转为"按用户任务"

新层级（自收 / 他收共用）：

1. **Hero（压缩）** — 金额从半屏主角降为身份确认，首屏让位给动作。
2. **吸顶分段器 Updates / Details** — 复用原设计的 tab 结构，`position:sticky; top:0` 固定，滚动不消失。
3. **Updates 页签**：
   - **Action Card（页面新主角）** — 唯一该做的事 + 24h 时效损失提示 + 单一主 CTA。这是"状态展示→交易推进"的支点。
   - **一句话状态** — 自然语言讲"卡在谁那"，替代 Sub-status 的内部说法。
   - **Transfer progress（折叠降级）** — 时间线节点逻辑一字未动，仅从"主体内容"降为"可展开查证的进度佐证"。
4. **Details 页签**：金额明细（你支付 / 汇率 / 你收到）。

### 3.2 自收 / 他收：共用结构，三处切换

| 元素 | 自汇自收 Self → Self | 自汇他收 Self → Others |
|---|---|---|
| 页面骨架 | 完全一致：Hero → 吸顶 Tab → (Updates: Action / 状态 / 折叠时间线) → (Details: 明细) | 同左 |
| Action 标题 | 去微信完成收款 / Finish collecting on Weixin | 提醒 LI SI 去收款 / Let LI SI know to collect |
| 主 CTA | 打开微信收款（深链拉起微信） | 提醒 LI SI 收款（拉起分享面板） |
| 时效损失指向 | 钱退回**你自己**账户，需重新设置 | 钱退回**你（汇款人）**账户，事没办成 |
| 一句话状态 | 等待你收款 / Waiting for you to collect | 等待 LI SI 收款 / Waiting for LI SI to collect |
| 次级操作 | 更改收款方式 | 更改 LI SI 的收款方式 |
| 降级反馈 | 去微信后："如果还没设置好，随时回来继续" | 通知后："已提醒，可重新提醒"（本端反馈） |

### 3.3 降级方案（应对"感知不到对方是否完成"约束）

- **他收点通知后 → 「已通知」态**：只给本端可确认反馈（已发送 / 可重新提醒），**不假装知道对方进度**，倒计时继续。
- **无微信 / 深链拉不起**：分享面板 Copy link 兜底。
- **自收去微信后回来**：不锁死，"如果还没设置好，随时回来继续"。

### 3.4 关键设计点 → 问题 → 原则

| 设计点 | 解决的问题 | 对应原则 |
|---|---|---|
| 信息架构翻转：Action Card 提到首屏、Timeline 折叠降级 | "回顾过去"占主位、"推进未来"被压末端；按后台模块组织 | L1-04、L1-05、L1-13、L1-03 |
| Action Card 明写"现在该做什么" + 一句话状态讲"卡在谁那" | 用户不知下一步、不知卡点；"Share to recipient"是内部说法 | L1-05 `P0`、L1-08 `P0` |
| 自收 / 他收分场景渲染（标题 / CTA / 损失指向切换） | 现页面不分场景，自收用户被要求"通知自己" | L1-08 `P0`、L1-01 |
| 单一主 CTA 直达：自收深链拉微信 / 他收拉分享面板 | 主操作埋在时间线末端、识别度弱、指向不清 | L1-07 `P0`、L1-09 |
| 24h 退回时效前置，framing 为"帮你避损"而非恐吓；他收指明"退回给你" | 用户不知有时限、无从感知紧迫；抓手强但易滥用 | L1-11 `P0`、L1-02 `P0` |
| 时效多线索表达（时钟图标 + 文案 + 琥珀色块 + 固定位置），非红色告警 | 关键时限若只靠颜色/灰字，部分用户漏读=没做 | L1-16 `P0`、L1-02 |
| Timeline 折叠为"3 of 5 done"可展开 | 四步+金额+汇率一次压上，认知负担过重 | L1-06 `P0`、L1-03 |
| 降级反馈态：只给本端"已提醒/可重发"，不谎报对方进度 | 约束下感知不到对方完成；点完通知无反馈易反复点 | L1-10 `P0`、L1-02 |
| Updates/Details 吸顶分段器 | 滚动时切换器消失、明细与推进内容混杂 | L1-06、L1-14 |
| 时间线节点文案与逻辑保持不变，仅调呈现权重 | 硬约束：不改 Timeline 节点、不新增后台能力 | （约束遵守，非原则驱动） |

**当前原则未覆盖标注**：24h 倒计时的**紧迫感应随剩余时间如何递进升级**（如剩 <2h 是否加强表达强度），L1 未覆盖——涉及情绪强度随时间的动态调节。原型采用保守的恒定琥珀色表达，未做"越临期越红"的升级，以免滑向 L1-02 的焦虑红线。

## 4｜设计反思：L1 能否有效指导「设计自驱类需求」

以本次「状态展示页 → 交易推进页」为试金石，评估 L1 对自驱类需求的指导力。

### 4.1 原则适用性

**扛得住**：重构主干判断 L1 提供了清晰依据（L1-04/05/08 支撑 IA 重排，L1-06/13 支撑降级与主次翻转，L1-16 支撑多线索时效，L1-02 守住 framing 红线），均真实用上。

**指导不足（恰在"自驱"上）**：

1. **L1 是"理解优先"而非"推进优先"**。全部 16 条底层动机是可用性/防错（Nielsen 系），而自驱类需求的本质是**主动推动用户完成待办**。L1 无一条正面讲"页面应主动降低未完成任务的阻力并正当驱动行动"；最接近的 L1-05 只到"知道下一步"（认知清晰），不到"推动执行"（行为推进）。
2. **持续用力的唯一抓手是防御性的**。L1-02 只讲"不能牺牲信任"（刹车），不讲"如何正当地推"（油门），体系面对自驱系统性偏保守。
3. **L1 全是静态快照，无时间维度**。倒计时、时限、过期、退回等"随时间演进的状态"一条未覆盖，而跨境汇款高频涉及结算窗口、汇率锁定、退款时限。
4. **反馈原则假设结果总能拿到**。L1-10 未覆盖"能力受限、拿不到完整结果时如何诚实反馈"，本次降级态全靠自行补位。

### 4.2 原则优化建议

| 现有原则 | 存在的问题 | 优化建议 |
|---|---|---|
| **L1-02** | 只有防御性表述，对"如何正当推动"零正向指导，自驱缺油门 | 补正向条款：允许并指导用真实利益/损失/时效/进度推进；给出"正当推进 vs 操纵"可判定边界（信息真实、无虚假稀缺、可退可控）。与新增推进原则成对制衡 |
| **L1-05** | 停在"认知清晰"，未延伸到"降低到下一步的行动阻力" | 扩展：不仅让用户**知道**下一步，还要主动**前置、直达**下一步动作，从"告知路径"升级到"铺好路径"（与 L1-09 咬合） |
| **L1-10** | 默认结果总能反馈 | 补边界条款：无法确认结果时给本端可确认反馈 + 明确标注不确定，禁止伪造/暗示未掌握的进度 |
| **L1-16** | 只讲静态状态多线索，未触及"随时间变化" | 补充"时效/倒计时属关键状态、需随时间清晰演进"，或独立成新原则（倾向独立） |

### 4.3 新增原则建议

| 建议新增原则 | 新增原因 |
|---|---|
| **主动推进任务完成**（战略/范围层）：设计不仅要让用户能完成任务，还应主动降低未完成任务的阻力、在正当前提下推动其尽快完成 | L1 通篇"理解优先、被动响应"，无一条讲"主动推进"。自驱类需求 = 主动推进。这条是 L1-02 的正向搭档（一推一防），缺了它体系只能靠设计者直觉补位 |
| **随时间演进的状态与时效表达**（结构/表现层）：涉及时限、倒计时、过期、退回时，应让"还剩多久、超时会怎样、当前紧迫程度"随时间清晰、诚实地演进 | L1 全是静态快照、零时间维度。跨境汇款高频高值涉及时效。本次"紧迫感如何递进"即无原则可依 |

### 4.4 原则质量评价

| 维度 | 评价 | 改进建议 |
|---|---|---|
| **完整性** | 可用性/理解维度完整；缺"行为推进""时间维度""诚实边界"，对自驱类不完整 | 补 4.2 / 4.3 缺口，尤其主动推进原则 |
| **一致性** | 结构统一、分层清晰，每条带"冲突取舍"；但制衡关系未显式化，易被误读为"清晰即可随便推" | 显式标注成对/制衡原则（推进 ⇄ L1-02），冲突取舍里点名对手条款 |
| **可理解性** | 高。"一句话+解决什么+核心判断+正反例+边界+取舍"模板对人和 AI 都友好 | 少数抽象表述（"符合心智""理解节奏"）可加可感知判定线索 |
| **可执行性** | 有正反例和取舍方向，强于口号；但多为定性、缺可判定阈值，落地依赖设计者水平 | 为 6 条 P0 各配轻量判定清单（3–5 可勾选项），把定性变可核对 |
| **可复用性** | 通用抽象得当、跨场景可复用；但遇"自驱/时效/多身份"须靠 L2/L3 补，且下沉时机全靠人工判断 | 建立"何时从 L1 下沉到 L2/L3"的触发指引 |

### 4.5 最需优先改进的三个方面

1. **补"主动推进"油门，并把 L1-02 明确升级为其制衡刹车**——现体系只有防御没有正向驱动，所有自驱类需求都在无原则区靠直觉裸奔。
2. **补"时间/时效"这一整个缺失维度**——L1 全静态，而跨境业务推力大量来自时效；既是自驱核心抓手，也是最大结构性盲区。
3. **把 P0 原则从"定性判断"推进到"可核对清单"，并打通 L1→L2/L3 下沉衔接**——解决"原则读得懂、落地靠人"的问题。

> **一句话总结**：L1 是一套优秀的「可用性 / 防错」底盘，但它假设产品是被动被使用的；一旦需求变成「主动推进用户完成任务」（自驱类），它就缺三样东西——**油门（推进原则）、时钟（时间维度）、把判断落到可核对的尺子（可执行性）**。
