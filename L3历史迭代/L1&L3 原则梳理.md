# L1-L3 原则层梳理

## L1-通用原则

> 当前进度：**`已完成`**
> 
> 以用户体验五要素为框架进行整理，包含战略层\*1 + 范围层\*1 + 结构层\*3 + 框架层\*6 + 表现层\*4，其中与业务相关的原则有 **`6`** 条。

| 序号 | 原则名 | 解释 | 业务相关 |
| --- | --- | --- | --- |
| L1-01 | 先确认用户为什么需要这个设计 | 设计首先要回答用户为什么需要它，而不是先假设功能本身天然成立。 |  |
| L1-02 | 不能为达成目标牺牲用户理解与信任 | 设计推动目标时，不能以牺牲用户理解、控制感和信任为代价。 |  |
| L1-03 | 先让用户完成核心任务，再补充更多内容 | 设计应先保证用户完成核心任务，再逐步补充其他信息和能力。 |  |
| L1-04 | 信息组织要符合用户心智 | 信息组织应优先符合用户的理解方式，而不是内部分类习惯。 |  |
| L1-05 | 让用户知道自己在哪，下一步去哪 | 用户完成任务时，应清楚知道当前在哪、接下来做什么、完成后去哪里。 | ✅ |
| L1-06 | 复杂信息要按理解节奏逐步展开 | 复杂信息应按用户当前理解和决策节奏逐步展开，而不是一次性全部压上来。 | ✅ |
| L1-07 | 界面要让用户一眼认出可操作项 | 界面应让用户一眼认出哪里可以点、选、输入或执行，而不是靠试错摸索。 | ✅ |
| L1-08 | 让用户清楚理解当前动作和结果 | 用户在操作前就应清楚理解自己在做什么，以及会得到什么结果。 | ✅ |
| L1-09 | 关键任务不要让用户多走弯路 | 完成关键任务的点击、输入和决策成本应尽量低。 |  |
| L1-10 | 重要操作后要及时反馈结果 | 用户完成重要操作后，应及时知道结果、当前状态和下一步。 | ✅ |
| L1-11 | 关键操作要先防错，再可退可恢复 | 关键操作要先尽量防错，再在出错后提供可退、可改、可恢复路径。 | ✅ |
| L1-12 | 同类交互应保持一致，别让用户反复重学 | 同类交互应尽量使用一致的规则和表达，减少用户重复学习。 |  |
| L1-13 | 视觉要先帮助用户分清主次 | 视觉呈现首先要帮助用户快速分清主次，而不是只追求好看。 |  |
| L1-14 | 相关内容要让用户一眼看出归属 | 界面应通过稳定的分组关系和视觉秩序，让用户一眼看出哪些内容属于一组。 |  |
| L1-15 | 信息要便于扫读和定位 | 文本和信息应便于用户快速扫读、查找和定位重点。 |  |
| L1-16 | 关键状态不能只靠单一线索表达 | 关键状态应通过多种清晰线索共同表达，不能只靠颜色或细微信号。 |  |

## L2 - 跨境支付平台原则

> 当前进度：**`已完成`**

| 序号 | 原则名 | 解释 |
| --- | --- | --- |
| L2-01 | Traceability / 可追溯 | 钱的去向必须全程可追溯 |
| L2-02 | Honesty / 透明 | 汇率口径必须明示来源、时效与计价时点 |
| L2-03 | Disclosure / 披露 | 合规披露必须前置于决策动作 |
| L2-04 | Safety / 安全 | 错误必须可防可救：前置防御 + 反悔窗口 |
| L2-05 | Distinction / 辨识 | 多币种共存必须强对比、防误读 |
| L2-06 | Trust / 可信 | 金额必须可信、可对账、可识别 |
| L2-07 | Predictability / 可预期 | 不确定性必须主动披露，不能等用户问 |

# 附录

## 1. 业务服务类型划分（共 9 类）

通用服务链路：

🟤 通知触达 / 功能入口 → ⚫ 前置指引 → \[ 🟢 授权确认 / 🔴 身份验证 / 🟠 选择方式 / 🔵 提供信息 /  🟣 开通服务 \] + ⚪ 合规判断 → 🟡 查看状态

通用服务框架：

**前往 → 指引 → 行动 + 检验 → 结果**

| 类型 | 分色 | 服务类型 | 解释 | 需求频率 | 设计参与度 | 典型场景 |
| --- | --- | --- | --- | --- | --- | --- |
| 前往 | 🟤 | 通知触达 | 平台主动向用户触达信息 | **中** | **中** | 1. 看到来自对方分享的<u>收款名片、收款卡片、代付卡片</u><br>2. <u>短信、公众号</u>推送收款通知、调单通知 |
| 指引 | ⚫ | 前置指引 | 在关键操作发生前提供说明与引导 | **低** | **中** | 1. <u>跳转汇款机构</u>指引<br>2. <u>sharelink 跳转通知</u>收款人<br>3. 留学缴费银行选择转账时，前置展示完整指引 |
| 行动 | 🟢 | 授权确认 | 用户对规则、协议、权限作出明确同意 | **高** | **中** | 1. 首次开户，选择收款方式前<u>签署协议</u><br>2. 新增渠道<u>补签协议</u><br>3. 留学缴费签署协议 |
|  | 🔴 | 身份验证 | 平台核实操作者为本人及其身份合法 | **低** | **低** | 1. 首次开户输入<u>支付密码</u>验证身份<br>2. 留学缴费银行选择转账时，<u>刷脸</u>验证身份 |
|  | 🟠 | 选择方式 | 用户在多个可选选项中做出决策 | **低** | **中** | 1. 对比选择汇款机构<br>2. 首次开户，选择<u>收款方式</u><br>3. 留学缴费选择<u>支付方式</u> |
|  | 🔵 | 提供信息 | 用户向平台录入或者补充所需材料 | **高** | **高** | 1. 风控调单提交<u>证明材料</u><br>2. 首次收款开户补充<u>完善个人信息</u><br>3. 填写留学缴费信息 |
|  | 🟣 | 开通服务 | 激活一项此前未具备的新功能 | **低** | **高** | 1. 开通<u>侨汇</u>服务 |
| 检验 | ⚪ | 合规判断 | 平台在后台对用户信息进行合规裁决 | **高** | **低** | 1. 收款开户时需实名认证、证件类型、影印件留存、姓名 / 手机号一致校验<br>2. 侨汇额度不足提示 |
| 结果 | 🟡 | 查看状态 | 用户获取当前业务所处的进度或结果 | **高** | **中** | 1. 点击收款后，给予订单状态<u>等待到账</u><br>2. 触发风控，订单页显示<u>异常状态</u> |
